# 설계: "검사 후 무엇을 알 수 있나요?" 카드 클릭형 전환 + 결과 3개 기능 추가

- **날짜:** 2026-08-14
- **대상:** 오션(OCEAN) 성격 검사 (정적 사이트: `index.html`, `app.js`, `styles.css`, `data/*.js`)
- **상태:** 승인됨 (사용자 승인 2026-08-14)

## 배경 / 문제

랜딩의 "검사 후 무엇을 알 수 있나요?" 섹션에는 6개 카드가 정적 `<div class="discover-card">`로만
존재해 클릭 반응이 없다. 사용자는 카드를 클릭하면 내용이 펼쳐지고, 그 내용이 **실제 결과의 예시
미리보기**이길 원한다.

실제 결과 페이지(`app.js`의 `finish()`)가 렌더하는 것은 레이더 차트·특성 슬라이더·유형 커버·
강점·블라인드스팟·한 줄 요약뿐이다. 6개 카드가 약속한 것 중 **3개(커리어 적합도·협업 인사이트·
표본 비교)는 실제 결과에 존재하지 않는다.** 따라서 "예시 미리보기"를 정직하게 하려면 이 3개
기능을 결과 페이지에 실제로 구현해야 한다. (사용자 결정: 실제 추가)

## 결정 사항 (사용자 확정)

1. **인터랙션:** 카드 안에서 펼치는 아코디언. 기존 FAQ의 네이티브 `<details>/<summary>` 패턴 재사용.
2. **미리보기 내용:** 실제 결과 컴포넌트의 예시 미리보기(고정 샘플 프로필 기준).
3. **없는 3개 기능:** 결과 페이지에 실제로 구현.
4. **표본 비교 기준:** 근사 규준값(평균·SD) 사용 → 대략 백분위. "근사 추정치" 미주 필수.
5. **카드 5 "성장 제안":** 신규 섹션 만들지 않고 기존 종합 분석(강점·주의점)에 매핑.
6. **표본 비교 랜딩 문구:** "일반적인 응답 분포와 비교" → "근사 기준과 비교"로 수정.

## 아키텍처 원칙

기존 `archetypes.js` 구조를 그대로 따른다: 특성 레벨(H/M/L)에서 파생하는 순수 빌더 함수를 만들고
`buildProfile()`이 조립. `app.js`가 렌더. 결과 렌더와 카드 미리보기는 **같은 렌더 함수를 공유**해
중복을 없애고 "미리보기 = 진짜 결과" 를 보장한다.

## 상세 설계

### 1. 데이터/로직 (`data/archetypes.js`)

기존 `levelOf`, `buildStrengths`, `buildBlindspots` 옆에 다음을 추가하고 `buildProfile` 반환값에 합친다.

- `buildCareer(FACTORS, levels)` → `{ roles: string[], note: string }`
  - 특성별 두드러진 레벨(H 또는 N-low)에 직무 태그를 매핑해 모음 → 중복 제거 → 상위 3~5개.
  - `note`: 가장 강한 특성 1~2개를 근거로 한 1문장. "성향 기반 추천 · 절대적이지 않음" 톤.
  - 태그 매핑(가이드, 카피는 기존 톤으로 다듬기):
    - O.high: 기획·R&D·콘텐츠·디자인 / O.low: 운영·품질관리·회계
    - C.high: PM·프로젝트관리·재무·엔지니어링 / C.low: 크리에이티브·초기 스타트업
    - E.high: 영업·마케팅·HR·PR / E.low: 연구·분석·개발·집필
    - A.high: 상담·CS·교육·조율 / A.low: 협상·감사·비평
    - N.low: 위기관리·리더십·고압 환경 / N.high: 리스크 감지·품질검수·안전관리
- `buildCollab(FACTORS, levels)` → `string[]` (불릿 3개; 기존 강점/블라인드스팟과 동일한 리스트 스타일)
  - 팀에서의 역할: 가장 강한 특성 기준 한 줄.
  - 소통 스타일: E(주도적/신중), A(조율형/직언형) 조합 한 줄.
  - 협업 팁: 주 블라인드스팟에서 도출한 한 줄.
- `buildNormComparison(pct)` → `Array<{ key, pct, percentile, band }>`
  - `NORMS` 상수(특성별 근사 평균·SD, **"근사 앵커, 실제 규준 아님" 주석 필수**):
    - O {mean:63, sd:16}, C {mean:61, sd:17}, E {mean:52, sd:19}, A {mean:68, sd:15}, N {mean:49, sd:19}
    - 값은 조정 가능한 단일 상수 블록으로. 실제 IPIP 규준 확보 시 교체.
  - z = (pct - mean)/sd → 정규 CDF 근사(`normalCdf`, Abramowitz-Stegun erf 근사)로 백분위.
  - `percentile`(하위부터 %), `band`("상위 약 X%" 표기용). 특성별로 반환.

`buildProfile` 반환 객체에 `career`, `collab`, `norms` 추가.

### 2. 렌더 (`app.js`)

- 상수 `SAMPLE_PCT` 추가 (예: 실행가형 `{O:62, C:82, E:48, A:66, N:35}`) — 카드 미리보기 전용.
- 결과 렌더 코드를 작은 함수로 추출해 결과·미리보기가 공유:
  - `renderTraitBars(container, pct, levels)` — 특성 미니 막대(카드1 미리보기 + 필요시 결과 재사용)
  - `renderNormBars(container, norms)` — 표본 비교 막대
  - `renderCareer(container, career)` — 커리어 섹션
  - `renderCollab(container, collab)` — 협업 섹션
- `finish()`: 기존 렌더 유지 + 새 3개 섹션(표본 비교·커리어·협업) 렌더 호출.
- 페이지 로드 시(또는 최초 랜딩 표시 시) `buildProfile(FACTORS, SAMPLE_PCT)`로 6개 카드
  아코디언 body의 미리보기 컨테이너를 채운다.

### 3. 마크업 (`index.html`)

- `#view-result`에 3개 섹션 추가. 순서:
  커버 → Big Five 프로필 → **표본 비교(NEW)** → 종합 분석 → **커리어 적합도(NEW)**
  → **협업 인사이트(NEW)** → 한 줄 요약
- 6개 `.discover-card`(div)를 `<details class="discover-card">` + `<summary>`(아이콘·제목·요약)
  + 미리보기 컨테이너(`<div class="dc-preview" data-preview="...">`)로 변경.
- 표본 비교 카드의 설명 문구를 "근사 기준과 비교"로 수정.

### 4. 스타일 (`styles.css`)

- `.discover-card`를 details로 바꾸며 summary 클릭 영역·＋/− 마커(FAQ 패턴 차용)·펼침 애니메이션.
- 신규 결과 섹션(표본 비교 막대, 커리어 태그, 협업 불릿) 스타일 — 기존 토큰(`--card`,`--line`,
  `--primary`,`--muted` 등)과 결과 페이지 톤 재사용. 새 하드코딩 색 최소화.

### 카드 → 미리보기 매핑

| 카드 | 미리보기(샘플 기준 실제 컴포넌트) |
|---|---|
| 1 5개 특성 백분위 | `renderTraitBars` 미니 막대 |
| 2 성격 유형 | 샘플 유형명 + 한 줄 요약 |
| 3 커리어 적합도 | `renderCareer` (NEW) |
| 4 협업 인사이트 | `renderCollab` (NEW) |
| 5 성장 제안 | 기존 강점·주의점 불릿 |
| 6 표본 비교 | `renderNormBars` (NEW) |

## 범위 밖 (YAGNI)

- 실제 IPIP 모집단 규준 데이터 수집(근사 앵커로 대체, 미주 표기).
- 카드 5 전용 "성장 제안" 신규 섹션(기존 종합 분석에 매핑).
- 결과 저장 스키마(Supabase) 변경 — 새 섹션은 클라이언트 파생이라 저장 불필요.

## 수용 기준

- [ ] 6개 카드 모두 클릭 시 펼쳐지고, 각기 대응하는 실제 결과 컴포넌트 미리보기가 보인다.
- [ ] 결과 페이지에 표본 비교·커리어 적합도·협업 인사이트 3개 섹션이 실제 데이터로 렌더된다.
- [ ] 표본 비교에 "근사 추정치" 미주가 있고, 랜딩 문구가 "근사 기준과 비교"로 바뀌었다.
- [ ] 미리보기와 결과가 동일 렌더 함수를 공유한다(중복 없음).
- [ ] 기존 검사·채점·이미지 저장·Supabase 저장 흐름이 그대로 동작한다(회귀 없음).
- [ ] 모바일(1열) 레이아웃에서 아코디언·신규 섹션이 깨지지 않는다.
